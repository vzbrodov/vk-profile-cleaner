# Проверка доступа к VK API

Скрипт требует Python 3.11+ и использует стандартную библиотеку.
Он вызывает только `users.get`, `messages.getConversations` и, если указан
диалог, `messages.getHistory`. Сообщения не удаляются и не помечаются прочитанными.

```bash
python3 -m unittest discover -s tests -v
python3 tools/vk_probe.py
python3 tools/vk_probe.py --peer-id 123456
```

Замените ID на свой тестовый диалог. Токен вводится локально скрытым вводом.
Не вставляйте его в команду, чат, issue или файл отчёта. Проверка не сохраняет
токен или переписку. Ответ содержит только результаты этапов и счётчики образца:
до одного диалога и до 20 сообщений. Это не полный анализ аккаунта.
Без `--peer-id` история не проверяется. Пустой образец — допустимый результат.

Версия API по умолчанию `5.199`, переопределяется `--api-version`.
Ошибки выводятся без сырого ответа сервера. Автоматических повторов нет:
при ограничении частоты сделайте паузу, при отказе доступа проверьте токен/приложение.
Таблица кодов: 5 — авторизация, 6 — частота, 9 — flood control, 15 — доступ,
29 — лимит. [Официальная схема ошибок](https://github.com/VKCOM/vk-api-schema/blob/master/errors.json).

Успешная диагностика подтверждает только чтение указанного образца. Она не
проверяет пагинацию, архив, удаление старых сообщений или удаление для всех.
Проверка удаления проводится позже отдельно: конкретное своё тестовое сообщение,
явное подтверждение, проверка результата вторым участником. Успешный HTTP-ответ
сам по себе не доказывает исчезновение у собеседника.

После проверки отзовите токен, если он больше не нужен. Для отчёта достаточно
даты, версии API, вывода счётчиков и кода ошибки; персональные данные не нужны.
